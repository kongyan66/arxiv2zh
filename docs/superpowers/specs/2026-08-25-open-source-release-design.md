# arxiv2zh 开源发布设计规格

日期：2026-08-25

## 概述

本次工作将现有 arxiv2zh 0.1.2 整理为可发布到
`github.com/kongyan66/arxiv2zh` 的标准社区开源项目。整理工作保持插件行为不变，
重点处理永久项目标识、仓库卫生、用户与贡献者文档、隐私和免责声明、自动检查及
GitHub Release 流程。

项目继续采用 `AGPL-3.0-or-later` 许可证。插件永久 ID 使用
`arxiv2zh@kongyan66`，发布后不再更改。

## 目标

- 清除模板残留、本机配置、调试数据和不应进入仓库或安装包的文件。
- 提供中英文用户文档及完整的安装、使用、开发和故障反馈说明。
- 明确第三方服务、Cookie、隐私、版权和翻译准确性边界。
- 提供贡献、安全披露、行为准则、Issue 和 PR 规范。
- 建立稳定、可复现的静态检查、单元测试、构建和 GitHub Release 流程。
- 检查源代码和构建产物中是否存在凭据、本机路径、Cookie 或签名 URL 泄露。
- 生成并验证可公开发布的 arxiv2zh 0.1.2 XPI。

## 非目标

- 改变翻译、登录、任务管理或附件导入行为。
- 重写现有模块架构或增加新功能。
- 承诺 hjfy.top 的可用性、接口稳定性或技术支持时限。
- 在公共 CI 中持续调用真实 hjfy.top 服务。
- 建立当前阶段不需要的维护者委员会、覆盖率门槛或签名提交制度。

## 仓库结构与发布边界

保留 `src/modules` 当前按职责划分的结构，只进行与公开维护直接相关的命名、类型、
注释和死代码清理。删除 Zotero 插件模板遗留文件、本地设计预览和无效文档入口。
设计规格与实施计划保留在 `docs/`，作为架构和维护参考。

`.gitignore` 必须排除 `.env`、`.scaffold`、`node_modules`、TypeScript 缓存、日志、
本地调试配置和系统文件。`.env.example` 只包含占位路径和变量说明，不包含任何真实
账号、令牌、路径或配置目录。

生产 XPI 只包含 Bootstrap、manifest、运行脚本、样式、图标、本地化和偏好页面等
运行资源。测试、设计文档、开发环境配置和本地任务数据不得进入安装包。

## 项目标识与版本

- GitHub 仓库：`kongyan66/arxiv2zh`
- npm 包名：`arxiv2zh`
- Zotero 插件 ID：`arxiv2zh@kongyan66`
- 首个公开整理版本：`0.1.2`
- Git 标签：`v0.1.2`
- 版本规范：语义化版本
- 许可证：`AGPL-3.0-or-later`

`package.json`、manifest 构建变量、更新地址、问题反馈地址、主页地址和 README 中的

## 用户与维护者文档

根目录 README 以中文为主，并链接英文 README。两种语言均说明：

- 功能、兼容的 Zotero 版本和支持的 arXiv 输入形式。
- 从 GitHub Releases 安装 XPI 的步骤。
- 右键菜单、快速输入、任务面板、登录和重新下载工作流。
- 设置项、数据存储位置、Cookie 生命周期和清除方法。
- 开发环境、常用命令、测试范围和构建方法。
- hjfy.top 未提供稳定公开插件 API 的兼容性风险。
- 问题反馈所需信息，以及提交日志前移除隐私数据的提醒。

新增并维护以下社区文档：

- `README.en-US.md`：英文用户与开发说明。
- `CONTRIBUTING.md`：Fork、分支、测试、提交和 PR 流程。
- `CODE_OF_CONDUCT.md`：社区行为准则及执行方式。
- `SECURITY.md`：支持版本、私密漏洞报告方式和敏感数据要求。
- `CHANGELOG.md`：按版本记录功能、修复和已知限制。
- GitHub Issue 模板：缺陷报告和功能建议。
- GitHub PR 模板：变更说明、验证和检查清单。

文档不声明尚未建立的邮箱、讨论区或响应时限。安全问题优先使用 GitHub 私密漏洞
报告功能。

## 隐私、第三方服务与免责声明

文档明确说明 arxiv2zh 是独立社区项目，与 Zotero、arXiv 和 hjfy.top 均无隶属或
官方认可关系。

登录发生在 hjfy.top 第一方页面。账号密码不会由插件读取或写入偏好设置；会话
Cookie 由 Zotero 内置 Firefox 配置存储管理，并可由用户从插件设置中清除。插件会
向 hjfy.top 发送用户主动提交的 arXiv 标识，并从 arXiv 获取公开论文元数据。

用户应自行确认论文、翻译结果及下载内容的使用符合适用许可证和法律。项目不保证
第三方服务持续可用、接口保持兼容或机器翻译结果准确。日志和问题报告不得包含
Cookie、签名下载 URL、账号信息或本机敏感路径。

## 代码质量与错误处理

整理遵循现有 TypeScript、Prettier 和 ESLint 规则。模块边界保持不变；只有在减少
真实重复、移除模板残留或澄清第三方协议边界时才调整代码。复杂协议字段和 Zotero
兼容性处理可保留简短注释，其余代码依靠清晰命名表达职责。

异常日志只记录诊断所需的状态、arXiv ID 和规范化错误，不输出请求 Cookie、认证
头、完整签名下载地址或本机文件路径。用户可见错误继续提供可执行的恢复操作，例如
登录、重试或重新下载。

## 测试与持续集成

每个提交和 PR 的公共 CI 执行：

1. Prettier 和 ESLint 检查。
2. TypeScript 类型检查。
3. 不依赖 Zotero 或网络的 Node 单元测试。
4. 生产 XPI 构建。
5. 构建产物上传，便于人工检查。

真实 Zotero 启动、登录页面和 hjfy.top PDF 下载属于本地发布前集成测试。它们不在
公共 PR CI 中调用，以避免图形环境差异、账号状态和第三方服务波动造成随机失败。
本地发布检查继续覆盖任务面板挂载、第一方登录页加载、真实译文 PDF 下载导入和
插件启动。

## 发布流程

发布者先更新版本号与 `CHANGELOG.md`，运行静态检查、单元测试、本地 Zotero 集成
测试和生产构建，并验证 XPI 压缩包内容。随后推送 `v*` 标签，由 GitHub Actions
调用 zotero-plugin-dev 的发布工作流创建 Release、上传 `arxiv2zh.xpi` 和更新清单。

发布工作流只申请创建 Release 所需的仓库权限。第三方可复用工作流固定到稳定版本
或提交哈希，避免长期跟随可变 `main` 分支。仓库不保存 GitHub Token；自动发布使用
GitHub Actions 提供的短期令牌。

## 验收标准

- 仓库内无凭据、Cookie、本机绝对路径、签名 URL 或调试数据。
- 所有项目标识和 GitHub 链接一致。
- 中英文 README、许可证、贡献、安全、行为准则和变更记录齐全。
- Issue/PR 模板可直接用于公开协作。
- 公共 CI 不依赖真实 Zotero GUI、账号或 hjfy.top 网络状态。
- 格式、ESLint、TypeScript、单元测试和生产构建通过。
- 本地 Zotero 集成测试通过。
- XPI 内容完整且只包含运行文件。
- `git status` 中只保留本次预期的开源整理变更。
