# arxiv2zh 快速上手网站设计规格

## 背景

arxiv2zh 已具备完整的插件功能、双语 README、GitHub Release 和自动化发布流程，但缺少面向首次用户的独立图形化教程。新页面参考 [pdf2zh-desktop macOS 使用教程](https://aarongig.github.io/pdf2zh-desktop/tutorial.html) 的清晰导航、真实截图和分步说明，内容与视觉重新针对 arxiv2zh 设计。

## 目标

- 提供一个可由 GitHub Pages 独立访问的中文快速上手页面。
- 在约两分钟的阅读时间内讲清安装、登录、翻译和结果归档。
- 通过产品化首屏介绍 arxiv2zh，同时让下载和开始使用保持直接。
- 使用脱敏后的真实 Zotero 截图，不暴露作者的文献库、账号或 Cookie。
- 自动部署教程，不干扰现有插件 CI 和 Release 流程。

## 非目标

- 不复制 README 的完整设置、开发、隐私和故障排查内容。
- 不建立多页面文档站、搜索系统、博客或版本化文档。
- 不引入 React、Vue、Astro、Vite 或新的前端构建依赖。
- 不在页面中嵌入 hjfy.top 登录态、账号信息或在线翻译交互。

## 目标用户与成功标准

目标用户是已经使用 Zotero、希望把 arXiv 论文翻译为中文 PDF，但不想配置 API Key 或本地翻译环境的研究者。

页面成功标准：

1. 用户在首屏理解 arxiv2zh 的用途、主要输出和第三方服务关系。
2. 用户可在一次点击内进入最新 Release 下载插件。
3. 用户能按页面顺序完成安装、登录和首次翻译。
4. 用户能确认中文 PDF 会自动成为原 Zotero 条目的子附件。
5. 桌面和手机视口下均无文字溢出、遮挡、空白截图或不可用链接。

## 信息架构

页面采用单页产品导览，共五个区块。

### 1. 顶部导航

- 左侧显示 `arxiv2zh` 品牌文字。
- 右侧提供“安装”“翻译”和“GitHub”入口。
- 桌面端使用轻量吸顶导航；移动端保留品牌、下载和菜单按钮。

### 2. 产品首屏

- H1 使用产品名 `arxiv2zh`，不使用抽象宣传语替代产品名。
- 支持文案突出“简单配置，在 Zotero 中获得排版完整的中文 arXiv PDF”。
- 主按钮为“下载插件”，链接到最新 GitHub Release。
- 次按钮为“查看源码”，链接到项目仓库。
- 首屏下半部分展示一张脱敏的 Zotero 插件真实截图，并在常见桌面和手机高度中露出下一部分内容。

### 3. 三步快速上手

按顺序展示三段全宽内容，每段包含编号、简短说明和截图：

1. 安装 XPI：下载 `arxiv2zh.xpi`，在“工具 -> 插件 -> 从文件安装插件”中安装并重启 Zotero。
2. 登录服务：从插件设置或任务面板打开 hjfy.top，完成一次登录；Cookie 由 Zotero 配置保存。
3. 翻译论文：选择含 arXiv 信息的条目或 PDF 附件，右键执行“arxiv2zh -> 翻译为中文”。

### 4. 完成结果

- 展示任务完成后的 Zotero 条目结构。
- 说明生成的中文 PDF 会自动成为对应条目的子附件。
- 简要说明服务使用 arXiv TeX 源码翻译和重新编译，尽可能保留公式、图表、引用和论文结构。

### 5. 页尾信息

- 显示 Zotero 7、8、9 兼容信息。
- 明确 arxiv2zh 是独立社区项目，hjfy.top 是第三方服务。
- 链接到仓库 README、隐私说明、Issue 和 GitHub 源码。

## 视觉规范

选用“A：产品导览”方向，以苹果产品页面的清晰层级、克制色彩和大留白为基调。

- 背景在 `#FFFFFF` 与 `#F5F5F7` 间交替。
- 正文使用近黑色，次要文字使用中性灰，品牌强调色使用墨绿色。
- 字体栈优先 `-apple-system`、`BlinkMacSystemFont` 和系统中文字体，不请求外部字体。
- 内容最大宽度约为 1120px，并使用稳定的响应式边距。
- 页面区块为全宽色带或无框布局，不把页面章节设计成漂浮卡片。
- 截图置于简洁的 macOS 窗口框中，仅使用细边框、轻阴影和不超过 8px 的常规圆角。
- 下载按钮可使用胶囊形态；图标按钮使用熟悉的图标并提供可访问名称。
- 不使用渐变、彩色光球、背景装饰圆或夸张视差。
- 动效仅包括导航状态、按钮反馈和轻微内容淡入，并遵循 `prefers-reduced-motion`。
- 颜色同时支持 `prefers-color-scheme: dark`，深色模式保持中性色背景和绿色品牌识别。

## 截图方案

使用隔离的 Zotero 测试配置重新制作截图，测试库只包含一篇公开 arXiv 示例论文。截图范围覆盖：

1. 插件安装入口。
2. hjfy.top 登录入口或账户页面按钮，不显示账号、Cookie 和个人信息。
3. 条目右键菜单中的“翻译为中文”。
4. 任务面板及完成后的中文 PDF 子附件。

截图应裁去与教程无关的文献库、操作系统菜单栏和个人目录。生成后再次检查文字、条目标题、窗口标题和状态栏，确认不包含私人数据。资源存放于 `docs/assets/images/`，使用描述性文件名和压缩后的 PNG 或 WebP。

## 技术结构

教程使用无构建步骤的静态文件：

```text
docs/
  index.html
  tutorial.html
  assets/
    tutorial.css
    tutorial.js
    images/
```

- `tutorial.html` 是完整教程页面。
- `index.html` 提供同内容入口或立即跳转到 `tutorial.html`，保证站点根路径可用。
- CSS 使用自定义属性统一颜色、间距和排版断点。
- JavaScript 只负责移动菜单、锚点状态和可选的视口淡入；禁用 JavaScript 后仍可阅读全部内容并使用链接。
- 所有外链使用 HTTPS；新窗口链接包含合适的 `rel` 属性。
- 图片设置明确宽高或 `aspect-ratio`，避免加载时布局跳动。

## GitHub Pages 发布

新增独立的 `.github/workflows/pages.yml`：

- 在 `main` 推送且 `docs/**` 或工作流本身变化时触发。
- 使用 GitHub Pages 官方 Actions 上传 `docs/` 并部署。
- 权限限制为 Pages 部署所需的最小范围。
- 使用独立并发组，避免重复部署互相覆盖。
- 不修改现有 `ci.yml` 和 `release.yml` 的职责。

首次发布时通过 GitHub 仓库设置或 API 将 Pages 来源设为 GitHub Actions。最终公开地址应为 `https://kongyan66.github.io/arxiv2zh/`，教程明确地址为 `https://kongyan66.github.io/arxiv2zh/tutorial.html`。

## 可访问性与降级

- 页面使用语义化标题、导航、主要内容和页尾元素。
- 所有截图提供说明操作目的的替代文本，不重复截图中每一个字。
- 键盘可访问导航、按钮和移动菜单，焦点样式清晰可见。
- 正文和交互控件满足可读的颜色对比度。
- 图片加载失败时，文字步骤仍完整说明全部操作。
- 页面在 320px 宽度下保持单列，不依赖横向滚动。

## 验证方案

1. 使用现有 Node 测试体系检查必需文件、主要锚点、Release 链接、仓库链接和图片引用。
2. 本地启动静态服务器，检查根路径与 `tutorial.html`。
3. 分别在桌面和手机视口进行截图验证，检查首屏构图、下一章节露出、截图加载、文字溢出和元素遮挡。
4. 使用键盘走查导航、按钮、菜单和焦点顺序。
5. 在启用和禁用 JavaScript、浅色和深色模式、减少动态效果下检查可用性。
6. 推送后检查 GitHub Actions 的 CI、Pages 部署和公开 URL。

## 风险与控制

- 第三方服务界面变化：教程仅描述稳定入口，避免依赖详细的网站内部步骤。
- Release 地址变化：下载按钮链接到 `/releases/latest`，避免硬编码版本号。
- 截图泄露私人信息：只使用隔离测试配置，并在提交前进行人工和自动尺寸检查。
- Pages 工作流影响发布：使用独立文件、独立触发条件和最小权限，不复用插件 Release 工作流。
- 页面内容过长：正文严格限制为快速上手，详细设置和故障排查继续链接到 README。
